## Material remaining implementation limits

- Real provider omits fundamentals, news/events and automatic corporate-action ingestion. It uses an operator-reviewed bounded universe; ambiguous securities are excluded conservatively. Explicit action adjustments and partial fills work, but automatic exchange/provider action discovery and liquidity modeling need integration. Unsupported exits block safely rather than being invented.
- A frozen-overlay comparison account, independently measured shadow promotion, automated calibration/causal patch evaluation and full performance attribution are not implemented. `shadow_then_promote` holds candidates and refuses a fabricated promotion. Soft strategy parameters are bounded prompt guidance, not hard execution permissions.
- Hosting privacy/deployment checks require real protected automation credentials. The bundled deployed-manifest checker is unauthenticated; protected sites retain PUSHED_UNVERIFIED unless an operator configures a verified mechanism. The private flag is an explicit operator acceptance, not automatic proof of hosting protection.
- The installed unprivileged model gateway uses kernel peer credentials and a systemd filesystem namespace verified to hide backend and Git paths. Its Codex authentication directory remains available to the model execution identity as required for login. Gateway request validation, process limits and read-only Codex flags do not substitute for comprehensive security auditing of the host and CLI.
- Meetings support frozen context, resume, deadline checks and partial participation; arbitrary historical reconstruction is intentionally unavailable. Actual token/cost telemetry is marked unavailable in this runner instead of fabricated.
- The frontend build validates exact generated JSON Schemas for manifest, overview, proposal candidates, manager decisions, reviews and accepted turns, as well as content hashes/routes/transcript equality. Full semantic cross-record review, issuer classification, protected-host access and real-provider fixtures still need production acceptance.

These boundaries are explicit in README and deployment documentation. Synthetic defaults permit a complete local demonstration without credentials, while this server now runs the configured forward paper schedule; remote publication still requires the listed hosting integration steps.
